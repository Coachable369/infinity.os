Native Qwen image engine port -- NOT INSTALLED / NOT RUNNABLE

This work is isolated from Hermes, Ministral, speech, and their model artifacts.
It does not add a selectable chat model or claim image-generation acceptance.
No inference server, Python runtime, Metal, CUDA, RPC, or network service is
part of the target configuration. Python/CMake are build-time tools only.

Two additional weak TLS initialization references appear in the diagnostic

  _ZTHN2sd15parallel_detail6activeE
  _ZTHN2sd15parallel_detail8executorE

Further runtime requirements already identified:
- ModelLoader::load_tensors creates std::thread even with n_threads=1;
  the current native compiler pthread bridge deliberately rejects thread
  creation. A reviewed serial loader or real native worker adapter is needed.
- Exceptions must terminate/quarantine an image job, never unwind into Rust
  or abort the kernel. The current compile flags are not proof of that boundary.
- Link and privately namespace the complete runtime before integrating it;
  these objects must NOT be linked unprefixed into the kernel.
- Bind immutable model reads and memory reservations to native capability
  authority; no ambient filesystem access or speculative large static heap.
- Pin/verify model components, generate actual pixels, support cancellation,
  save authorized Downloads objects, then connect thumbnails and previews.
- Keep Hermes default; add genuine readiness only after the backend and model
  package pass acceptance. Both architectures and fresh installations matter.

Reproduction (all commands require the build kit):
  ./build-kit run python3 tools/voice-native-runtime/newlib.py
  ./build-kit run python3 tools/voice-kokoro/prepare-native.py
  ./build-kit run python3 tools/image-native/prepare.py
  ./build-kit run python3 tools/image-native/prepare-runtime.py
  ./build-kit run python3 tools/image-native/native-build.py
  ./build-kit run python3 tools/image-native/link-native.py

Default target is ARM64. For x86_64 use INFINITY_VOICE_TARGET=x86_64 in the
build-kit command environment for each target-dependent step; the variable
selects the shared native toolchain adapter, not a speech-model modification.

The port remains outside release profiles until these gates pass. Do not use
object compilation, symbol inspection, or a failed link as inference evidence.
