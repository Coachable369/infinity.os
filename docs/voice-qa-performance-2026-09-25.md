## Audio corrections

1. The speech worker could skip PCM conversion after its synthesis deadline,
   yet publish Ready when the provider returned success. The final publication
   now rechecks the monotonic deadline, not only the explicit cancellation flag.
   Late work becomes Cancelled and cannot reach hardware playback.
2. Voice previously watched the shared chat generation state without identifying
   its own turn. A later typed request could be spoken or cancelled by voice.
   Accepted turns now have a sequence independent of bounded history rollover.
   Voice records its accepted turn and stops on replacement without cancelling
   that replacement. Accepted native input storage is also erased immediately.

`tools/voice-output-test.rs` executes the production Rust output job with
deterministic clock, authority, provider and hardware seams. It tests deadline
expiry despite provider success, overlap rejection, invalid authority/input,
wrong-owner cancellation, cancellation before worker completion and after Ready,
no unexpected hardware submissions, and successful subsequent playback. It is
not a physical-device or recognition-quality test.

Passing commands:

- `make audio-test voice-vad-test voice-pcm-test voice-indicator-test`
- `make voice-output-test` (three tests, including actual PCM conversion tests)
- `make voice-recognition-test voice-synthesis-hardware-test`
- `make ai-test` (includes turn identity/history rollover, worker scheduling and
  quantized arithmetic regression coverage)

The native recognizer fixture still misrecognizes “ten meters” as “ten years”,
matching the upstream reference. This remains an accuracy limitation, not a
successful real-user conversation. The separate fresh-install disk remains at
new-account password setup; no credential was created by automation. The upgraded
copy of the previously configured private disk booted without the ISO and reached
the desktop. Native `voice say hello from infinity` playback was confirmed audible
by the user. `voice listen` reached the visible LISTEN state. Live utterance
recognition and the complete Hermes spoken-response loop did not pass: during
LISTEN, the guest clock fell behind and command handling became severely delayed.
The last captured status had microphone level 0 and no recognition work. This is
not evidence that a live utterance reached the recognizer.

The stop command eventually completed and the widget returned to VOICE OFF.
VirtualBox input was temporarily disabled with `controlvm audioin off`; output
remained enabled. Do not treat that diagnostic workaround as an audio fix.
The VM process consumed approximately 790% host CPU; its log reported a 92-second
catch-up failure. A two-second host sample is retained at
`/tmp/voice-qa-vbox-capture.sample`. BSP register samples were in firmware-address
code rather than the kernel image. These observations do not yet isolate the
cause to the HDA driver, firmware callbacks, or the host backend. No speculative

not a clean comparison environment.

## Hermes experiment

Environment: native ARM64 host running the production model/runtime, seven
matrix workers, Hermes-3-Llama-3.2-3B Q4_K_M, unchanged context and decoding.
Prompt: “Explain what an operating system does in one sentence.” Five alternating
baseline/candidate trials require identical final generated bytes and 25 tokens.
The VM was paused for both sides of this controlled comparison, then resumed.
Model loading precedes the timing boundary. This is **not installed guest or
widget presentation latency**.

| Metric (median) | Before | After |
|---|---:|---:|
| Submit to complete response | 1.232302 s | 1.161132 s |
| First token | 0.478155 s | 0.441051 s |
| Steady decode interval | 0.726906 s | 0.697809 s |
| Steady decode throughput (24 intervals) | 33.02 tokens/s | 34.39 tokens/s |

Complete-response reduction: **5.78%**, below the requested 25%.
Change: `kernel/runtime/ai/qwen/workers.rs`, matrix claims reduced from 128 to
32 rows. All available configured workers remain eligible; disjoint output
ranges, cancellation and bounded UI-side polling are unchanged. Smaller claims
reduce the last-worker tail without changing model capabilities or arithmetic.

Five paired four-turn runs with the fixed prompt “Reply with only the word
Hello.” preserved exact generated output on every turn. Complete-response
changes were -1.88%, +3.36%, +4.59%, +0.57% (positive means faster). The first
short turn regressed slightly; do not describe the gain as uniform.

Rejected experiments: borrowing layer metadata instead of copying it per poll,
and a two-row Q4 tile did not establish a response-time gain and were reverted.
Initial runs with the active VM consuming about five host cores were noisy and
are not used for improvement claims. A host sample recorded 2.8 GiB peak process
footprint; this is not installed total RAM or a before/after memory comparison.

Structured receipts retained in:

- `build/hermes-audio-qa-rows32/result.json`
- `build/hermes-audio-qa-multiturn-isolated/results.json`
- `build/voice-whisper/aarch64/verified-hvf.json`

Installed follow-up must measure the same prompt, full completion/presentation,
CPU utilization and UI responsiveness. Do not extrapolate the native-host
numbers into the installed desktop or claim the 25% target is complete.
