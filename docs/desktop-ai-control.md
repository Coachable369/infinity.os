# Desktop AI control

Desktop chat and accepted voice transcripts share `AiRuntime::submit_chat`.
The following tools use the existing desktop launch workflows:

| Request | Surface |
| --- | --- |
| Open text editor | Text Editor |
| Open file navigator | File Navigator, Home location |
| Open browser | Infinity Browser, preserving existing tabs |
| Open settings | Settings |
| Open terminal | Command Window |
| Open task manager | Task Manager |
| Open app launcher | Installed application launcher |

Exact open/launch/start requests and common aliases work without waiting for
model weights. Hermes/Ministral receive the bounded tool vocabulary with each
desktop request and interpret other wording, such as "Bring up the app where I
can edit a text file." Ordinary conversation remains streamed. The old bootstrap
models support the exact-command path, not transformer paraphrase resolution.

## Execution boundary

The native model may propose one `OS_OPEN:<identifier>` record. Only a complete,
allowlisted record ending at the model's real completion token is accepted.
Partial tokens, unknown identifiers, arbitrary arguments, trailing commands,
and truncated inference cannot execute. Protocol records are not spoken or
displayed as normal replies. App-panel generations never enter this dispatcher.

The UI thread consumes a proposal once and rechecks the authenticated user,
unlocked desktop surface, and AI permission before calling the ordinary app
workflow. Changing users or cancelling clears queued proposals. The native
model cannot execute a shell, delete data, change permissions, or shut down.
These tools only open surfaces; they do not grant a background agent authority.
Normal task admission failures are reported as failures, not successful opens.

The execution receipt is supplied by the OS after checking window state, not
generated by the model. Voice uses the same receipt and the existing independent
speech-output permission. Editing/saving documents remains in the app assistant.

## Verification

Run through the build kit:

```sh
./build-kit run make ai-test editor-assistant-test
./build-kit run cargo run --quiet --release --manifest-path tools/behavior-harness/Cargo.toml --bin ai-test -- --control-native
```

The host contract exercises all seven typed commands, malformed/incomplete
model records, exact-once consumption, permission denial, cancellation, owner
changes, and failed-dispatch state. The native test loads the real Hermes model
and checks typed proposals for seven paraphrases plus non-command requests.
It does not claim to prove GUI launches: that requires live and installed VM
interaction. The command implementation is part of the shared kernel, with no
additional payload files or host service. Existing installed-kernel byte parity
checks cover its inclusion in the fresh-install payload.

Validated on 2026-10-09:

## Voice identity correction

Voice capture authority is session-scoped, but desktop conversation history and
OS command ownership are user-scoped. Voice startup now resolves the active
session's user before binding chat. Passing the session ID previously caused a
valid command to be rejected by the desktop's user-ID check, and could reset
the user's conversation at voice startup. The voice fixture now deliberately
uses different IDs and asserts the user binding; all 25 controller tests pass
(`20261009T205129574458Z-29606.json`). Lock/logout validation still uses the
session ID, so the fix does not weaken audio authorization.

Common polite request prefixes, trailing "please", whitespace, and terminal
speech punctuation are accepted by the deterministic command resolver. Host
acceptance verifies that these requests queue their typed actions with zero
LLM output tokens, while negated and compound requests do not take that path
(`20261009T205148733617Z-29644.json`). This removes language-model inference from
those requests, not Whisper transcription time. No speech decoder settings or
recognition-accuracy tradeoffs are changed.

The unchanged native Whisper decoder was measured separately on the standard
10-second JFK recording: 2.550 seconds initially and 2.627 seconds after Kokoro
synthesis, with correct recognition in both cases. This is freestanding ARM64
QEMU HVF evidence, not installed microphone or end-to-end UI latency
(`20261009T205214064758Z-29905.json`).

The corrected focused ISO builds passed for x86_64
(`20261009T205247184624Z-30001.json`) and aarch64
(`20261009T210623332338Z-34869.json`). Installed-kernel and boot-loader byte
parity passed on both (`20261009T212218514120Z-39812.json`). These are not
clean-release or installed GUI acceptance claims.
